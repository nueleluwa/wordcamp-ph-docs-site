# Post-Event Report Guide

**Purpose:** The structure for the comprehensive report submitted to WordCamp Central, shared with sponsors, and published for the community — required within 1 month of the event (see [post-event/post-event-workflow.md](post-event-workflow)).

**Owner:** Lead Organizer, compiling input from every Team Lead.

## Report structure

| Section | Content |
|---|---|
| Executive Summary | Brief overview of event success |
| Attendance | Number of attendees, demographics, growth from previous year |
| Speakers | Number of speakers, topics covered, speaker satisfaction |
| Sponsors | List of sponsors, revenue generated, sponsor satisfaction |
| Financial Summary | Budget vs. actual, revenue sources, expenses |
| What Worked Well | Successful strategies and initiatives |
| Areas for Improvement | Challenges and lessons learned |
| Community Impact | Feedback highlights, testimonials, media coverage |
| Recommendations | Suggestions for next year's team |

## Where each section's data comes from

- **Attendance, Speakers, Sponsors** — pull directly from the dashboard databases, not memory. See [reporting-and-kpis/dashboard-and-tracking-setup.md](../reporting-and-kpis/dashboard-and-tracking-setup).
- **Financial Summary** — from the reconciled books, per [planning/budget-and-finance-principles.md](../planning/budget-and-finance-principles).
- **What Worked Well / Areas for Improvement** — from the internal review meeting and compiled feedback surveys. See [post-event/post-event-workflow.md](post-event-workflow) "Within 2 Weeks."
- **Recommendations** — this section is the primary mechanism for institutional memory. Write it for someone who has never organized WCPH before; if a recommendation only makes sense to people who were in the room, rewrite it.

## Distribution

1. Submit to WordCamp Central (required).
2. Share with sponsors — this can be adapted from or paired with the sponsor thank-you in [sponsorship/sponsor-lifecycle-and-fulfillment.md](../sponsorship/sponsor-lifecycle-and-fulfillment).
3. Publish a public summary for the community, distinct from the internal version — the public version omits sensitive financial detail and individual performance notes.

## Feeding next year

Every "Recommendation" in this report should end up as either an update to the relevant playbook in this documentation set, or a new row in [organisation/open-decisions-and-gaps.md](../organisation/open-decisions-and-gaps) if it's a decision rather than a process fix. A recommendation that lives only inside this one report and nowhere else in the documentation will be forgotten by next year's team.
