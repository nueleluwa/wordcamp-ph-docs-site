# Issue Response Playbook

**Purpose:** A pre-agreed response and owner for the problems most likely to happen on event day, so nobody has to improvise in the moment. This is the event-day extension of [organisation/accountability-and-escalation.md](../organisation/accountability-and-escalation).

**Owner:** Whoever is nearest reports it. The named contact below owns the resolution.

## Common issues & solutions

| Issue | Solution | Contact |
|---|---|---|
| Power outage | Switch to generator backup | Logistics Lead |
| Internet down | Use mobile hotspot backup | Tech Lead |
| Speaker no-show | Find backup speaker or extend Q&A | Program Lead |
| AV equipment failure | Use backup equipment | AV Technician |
| Catering delay | Communicate to attendees, adjust schedule | Logistics Lead |
| Medical emergency | Call emergency services, use first aid kit | Lead Organizer |
| Attendee complaint | Listen, document, escalate if needed | Lead Organizer |
| Overflow crowd | Open overflow room with live stream | Logistics Lead |

## How to use this table

1. **Identify the issue** against the table above. Most on-the-day problems are already covered.
2. **Contact the named owner directly**, not the general Organizers Group, so the right person is alerted without delay.
3. **If it's not on this table**, escalate to the command center (see [event-day/operations-runbook.md](operations-runbook)) rather than guessing. The Lead Organizer makes the call on anything unlisted.
4. **Document it** regardless of outcome. Every event-day issue, resolved or not, gets logged for the post-event review. See [post-event/post-event-workflow.md](../post-event/post-event-workflow) "Internal Review."

## Code of Conduct and safety issues

<Callout type="error">
  Harassment, safety, or Code of Conduct violations do **not** go through the general complaint row above. They escalate immediately and directly to the Lead Organizer, regardless of severity. See [policies/code-of-conduct-and-safety.md](../policies/code-of-conduct-and-safety).
</Callout>

## Backup systems this playbook assumes exist

This table only works if the backups it refers to were actually set up in advance:

- Generator with confirmed fuel: [venue-and-logistics/nigerian-logistics-checklist.md](../venue-and-logistics/nigerian-logistics-checklist) "Power & Electricity"
- Mobile hotspot(s): same checklist, "Internet Connectivity"
- Backup AV equipment on standby: same checklist, "Audio/Visual Equipment"
- Backup catering vendor contact: same checklist, "Catering & Refreshments"
- First aid kit and nearest hospital identified: same checklist, "Venue & Facilities"

Verify every one of these during setup day. Don't assume "it was arranged months ago" is good enough.
